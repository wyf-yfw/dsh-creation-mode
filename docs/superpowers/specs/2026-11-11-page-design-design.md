# 创作模式：从「只做视频」扩展到「视频 + 前端页面设计」

日期：2026-11-11
状态：待确认

## 一、要解决的问题

现在的创作模式只有一个产物：**视频**。六个工具（`list_styles` / `show_stills` / `get_style` /
`save_storyboard` / `save_animation` / `get_reference`）从头到尾服务于「分镜 → 动画 → 导出 MP4」。
卡片的全部交互（时间轴、配乐、格式、导出目录）也是围绕视频建立的。

用户想要的是：**同一个模式里，既能做视频，也能做前端页面的设计。**

## 二、为什么是现在

1. 333 种风格里，配色、字体、排版取向对页面同样成立，风格库不必重建。
2. `references/` 里已有 `typography.md`、`color.md`、`motion.md`，页面需要的排版与调色知识大部分已经在了。
3. 页面是单文件 HTML，和现有「单文件 + 浏览器渲染」的架构同构，不需要引入构建链。

## 三、目标与非目标

**目标**

- 用户在同一模式下说「做一个落地页」，能拿到一个**双击就能在浏览器打开、能点、能滚动**的页面
- 视频与页面共用风格库、共用门禁结构、共用卡片语言
- 页面支持滚动进场、悬停等轻动效（复用 motion-prompt 的 `ui` / `lp` 词表）

**非目标**

- 不做多文件工程（React/Vue/构建工具），产物永远是单个 `.html`
- 不做后端、不做表单提交、不接数据库
- 不接真实业务：表单只做前端校验不发送，列表和图表用假数据
- 不替代设计工具（Figma），产出的是可运行的页面而不是设计稿
- 不新增「页面风格库」——先用现有 333 条

**反目标（做成了也算失败）**

- 页面卡片退化成「一个 iframe 截图」，用户拿不到能用的文件
- 视频流程被页面流程污染，原有门禁变松

## 四、考虑过的三条路

| 方案 | 产物 | 代价 |
|---|---|---|
| A. 页面与视频并列 | 可运行的单文件 HTML | 要新增工具、卡片、流程分支 |
| B. 页面 + 滚动动效 | 同上，页面里有进场/悬停/视差 | 同上，多一份动效词表 |
| C. 只出设计稿 | 长图或滚动视频 | 用户拿不到能用的东西，等于放弃「前端」 |

**选 B。** 它和 A 的实现成本几乎一样，多出来的滚动动效才是现有能力的自然延伸；
C 只是把页面拍成视频，对「前端设计」这个诉求没有回应。

## 五、怎么工作

### 5.1 第一步先分岔

`flow.js` 的第 1 步改成先判断**这次做什么**：

```
用户说要做什么
  ├─ 视频 / 短片 / 宣传片 / 动画     → 现有视频流程
  └─ 页面 / 落地页 / 官网 / 界面设计  → 新增页面流程
```

判断依据是用户的原话，不问「你要做哪种」——用户已经说了就不要再问一遍。
只有真的听不出来时才问一句。

### 5.2 页面流程（四步，两道门禁不变）

```
第 1 步 问清要做什么（受众、内容、基调、参考）
第 2 步 推荐风格 + show_stills（复用）
第 3 步 等用户拍板风格（硬门禁，复用）
第 4 步 出区块清单 save_outline（新工具）
第 5 步 等用户拍板区块（硬门禁，新）
第 6 步 写页面 save_page（新工具）→ 卡片预览 + 下载
```

区块清单对应视频的分镜：每个区块写清「这一段要说什么、放什么内容、用什么版式」。
页面没有时间轴，所以清单里没有秒数。

### 5.2.1 「能点」到什么程度

产物要在 `file://` 下直接可用，所以**不允许 ES module、不允许 fetch 本地文件、
不允许外链 CDN**——全部内联。

| 允许 | 例子 |
|---|---|
| CSS 交互 | hover、focus、active、`:checked` 驱动的展开 |
| 滚动动效 | IntersectionObserver 进场、滚动视差、sticky |
| 原生 JS 交互 | tab 切换、手风琴、模态、下拉、轮播、数字滚动 |
| 前端校验 | 表单必填、格式提示——**只提示不提交** |
| 假数据 | 图表、列表、表格用写死的示例数据 |

| 不允许 | 原因 |
|---|---|
| fetch / XMLHttpRequest | `file://` 下跨域，必然失败 |
| `<script type="module">` | 同上 |
| 外链字体、图片、CDN | 断网或离线时页面垮掉 |
| 真实接口、登录、支付 | 非目标 |

### 5.3 新工具

**`save_outline`** —— 提交页面区块清单

```
参数：title, style_id, sections[{ name, purpose, content, layout }], aspect
返回：区块卡片（可折叠的结构预览）
```

**`save_page`** —— 提交页面本体

```
参数：title, style_id, outline_id, html, duration(可选，用于进场动效时长)
返回：页面卡片（iframe 预览 + 宽度切换 + 下载）
```

校验与 `save_animation` 同级：必须单文件、不引用外部资源、含 `<meta name="viewport">`、
必须有至少一个区块（`<section>` 或等价结构）。

### 5.4 卡片长什么样

```
┌────────────────────────────────────────────┐
│ ● 落地页 · 暗色科技        [桌面][平板][手机]│
│ ┌────────────────────────────────────────┐ │
│ │  首屏标题                              │ │
│ │  ──────                                │ │
│ │  [ 按钮 ]                              │ │
│ └────────────────────────────────────────┘ │
│ 1440 × 900 · 4 个区块      [下载 HTML] [复制代码] │
└────────────────────────────────────────────┘
```

宽度切换只改 iframe 宽度（1440 / 834 / 390），页面自己响应式。
下载走现有的 export 通道，但文件名是 `.html`，不经过录制。

### 5.5 风格库怎么用

333 条风格原本是「动画风格」，用在页面上时只取其中的**配色、字体、质感**三样，
运动相关的描述忽略。这一点要写进 `get_style` 的返回提示里，避免 Agent 把
「镜头推进 3 秒」这类东西塞进页面。

### 5.6 新参考

- `references/page.md` —— 版式：网格、间距阶梯、区块类型、响应式断点、对比度
- `references/moves.md` —— 从 motion-prompt（MIT）整理的动效词表：名称、时长、参数，
  页面进场和悬停从这里取

## 七、已定的判断（实现时按这些走）

- 页面预览默认宽度 **1440**，可切 834 / 390
- 区块清单带「文案」列——页面上的字比视频更密，先定文案再排版
- 下载 HTML 时**不**附带截图，保持单一产物
- 这次只做 `page.md`；`moves.md` 单独一轮（192 条要逐条整理，不塞进这一版）

## 八、成功的样子

用户说「给我做一个 SaaS 落地页，暗色科技风」，之后：

1. 看到 2–3 张风格参考图，点选一张
2. 看到区块清单（首屏 / 特性 / 案例 / 价格 / 页脚），改两句，点确认
3. 拿到一张卡片，能在桌面/手机宽度下切换预览，点「下载 HTML」得到一个双击就能打开的文件
