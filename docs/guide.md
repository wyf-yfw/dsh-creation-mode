## 流程门禁

六步流程与两道确认门禁写在系统提示中（`plugin/flow.js`，段落序号 450，位于策略区）。
门禁的用途是控制返工成本：

| 门禁 | 原因 |
|---|---|
| 推荐风格时必须调用 `show_stills` | 文字描述不足以判断视觉风格 |
| 风格确认前不写动画代码 | 风格错误意味着整段重做 |
| 分镜确认前不写动画代码 | 分镜是结构调整成本最低的阶段 |

`save_animation` 未携带 `storyboard_id` 时，预览卡片会标注「未经用户拍板」。
用户若在首条消息中同时给出风格编号与内容，可跳过前三步，分镜确认不可跳过。

## 做视频还是做页面

第 0 步用用户的原话判断，不问「你要做哪种」：

| 信号 | 走哪条 |
|---|---|
| 视频、短片、宣传片、动画、片子、预告、MV | 视频流水线 |
| 页面、落地页、官网、主页、界面、UI、网页、设计稿、组件 | 页面流水线 |
| 都没提 | 追问一句用途再判断 |

判断结果说一句「这次做页面。」，定下后整条会话只走一条线。

| 视频 | 页面 |
|---|---|
| 问需求 → 推荐风格 → 拍板风格 | 同左 |
| 分镜（`save_storyboard`，带秒数） | 区块清单（`save_outline`，无秒数） |
| 拍板分镜 | 拍板区块 |
| 动画（`save_animation`） | 页面（`save_page`） |
| 卡片：预览 + 导出 MP4 | 卡片：桌面/平板/手机预览 + 下载 HTML |

页面产物是单文件 HTML，双击就能在浏览器打开、能点、能滚动；不接真实业务。

## 工艺参考

流程提示词只写「做什么、按什么顺序」，具体「怎么做」拆成 13 份按需加载的文档，
由 `get_reference` 一次取一份。完整清单见 [工艺参考](references.md)。

关键是**加载时机**——四份必须在早期步骤取，否则后面全错：

```
第 3 步 拍板风格后
  ├─ color        定调色板
  └─ typography   定字号阶梯
        ↓ 字号没定，不知道一条字幕能放几个字

第 4 步 出分镜前
  ├─ sequencing   时间轴、节奏曲线、疏密
  ├─ audio        卡点怎么落
  └─ copy         字幕硬规则
        ↓ 分镜就是时间轴，这里节奏错了后面全错

第 6 步 写代码前
  └─ motion（必取）+ 按需 7 份

交付前
  └─ 自检三条：三帧非黑屏 / 无随机数 / 每个 impact 有声音
```

一条 30 秒的片子通常取 3–5 份。全取 13 份反而抓不住重点。

## 示例输入

在创作模式下用自然语言描述需求即可。

| 输入 | 行为 |
|---|---|
| `想做个视频，讲我们这次把首屏从 3.2 秒压到 0.8 秒` | 提出澄清问题：受众、画幅、时长、调性 |
| `帮我挑个适合讲「三个人同时改一份文档」的风格` | 返回 2–3 个候选并附参考静帧 |
| `就第二个` | 读取该风格规范，提交分镜草稿待审 |
| `第 2 场拉长到 3 秒，结尾加一句「这次真的快了」` | 更新分镜并重新提交 |
| `可以，开始做` | 编写动画，输出预览卡片 |
| `用 B3 做一个 3 秒的粒子聚形，内容是 XXX` | 跳过前三步，仍先提交分镜 |
| `换个水墨风的，竖屏 9:16` | 按 Z 系列重做，画布改为 1080×1920 |

示例：

```text
想做一个 8 秒的竖屏短片，讲「首屏加载从 3.2 秒压到 0.8 秒」，
发在朋友圈，要爽快、有冲击力，主色 #4D6BFE。

用 A1 字雨做一个 5 秒的动画：屏幕上不断落下「已读」「未回」「在吗」，
越堆越多，最后压成一堵墙。16:9，30fps，深色背景。

用 O96 奥本海默风格做一段 4 秒的粒子火球，主题是「我们发布了一个东西」，
要黎明前试验场的质感，IMAX 颗粒。
```
